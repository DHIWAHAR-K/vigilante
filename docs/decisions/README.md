# Architecture Decision Records

Use an ADR for a choice that is expensive to reverse or constrains multiple parts of Vigilante. Copy `0000-template.md`, assign the next four-digit number, and use a short kebab-case title.

ADR states are `Proposed`, `Accepted`, `Superseded`, and `Rejected`. Accepted ADRs are immutable except for corrections that do not change the decision; supersede a changed decision with a new ADR that links to the old one.

Expected early records cover the desktop/UI stack, application boundaries, persistence and migration, local model runtime, web retrieval, security/privacy model, and packaging/distribution.
